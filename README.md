# Modbus RTU 多路继电器 —— Home Assistant 集成

把中盛科技 16 路（支持 1~72 路）RS485 继电器模块接入 Home Assistant。
模块经 **RS485 转 TCP 透传设备** 联网（TCP Server 模式），集成直接建立长连接发送
**Modbus RTU 原始帧**（无 MBAP 头），不依赖 pymodbus，零第三方依赖。

## 已完成的配置

| 项目 | 值 |
| --- | --- |
| 集成 domain | `modbus_relay` |
| 安装路径 | `/config/custom_components/modbus_relay/` |
| HA 中的设备名 | 灯光继电器 |
| 透传设备 | `192.168.100.254:23` |
| 模块站号 | 1（模块出厂默认） |
| 回路数量 | 16 |
| 状态轮询 | 10 秒 |

已生成的实体（`回路 1` ~ `回路 16`）：

```
switch.deng_guang_ji_dian_qi_ch1   ...   switch.deng_guang_ji_dian_qi_ch16
```

## 协议映射

来自《多路继电器输出系列使用手册》V2.1：

- 线圈 `0000H` ~ `0047H` → 通道 1 ~ 72（写 1 吸合，写 0 断开）
- 功能码 `0x01` 读线圈状态 → 轮询回读
- 功能码 `0x05` 写单个线圈 → 开关控制
- 默认参数：站号 1、波特率 38400、8N1、无校验（铁壳系列默认 9600）

示例帧（与手册逐字节核对一致）：

```
打开第 1 路： 01 05 00 00 FF 00 8C 3A
关闭第 1 路： 01 05 00 00 00 00 CD CA
读 16 路  ： 01 01 00 00 00 10 FD C6
```

## 添加/修改配置

**设置 → 设备与服务 → 添加集成 → 搜索「Modbus RTU 多路继电器」**

| 字段 | 说明 |
| --- | --- |
| IP 地址 / 主机名 | 透传设备的地址，如 `192.168.100.254` |
| TCP 端口 | 透传设备监听端口，如 `23` |
| 设备站号 | 模块地址 1~255，出厂默认 1 |
| 继电器回路数量 | 1~72，填 16 就生成 16 个实体 |
| 设备名称 | 决定实体 ID，如填「灯光继电器」→ `switch.deng_guang_ji_dian_qi_*` |
| 状态轮询间隔 | 秒；填 0 表示不轮询，只发指令不回读 |
| 回读继电器状态 | 开启后每轮用 `0x01` 读真实状态并校正 UI |

添加后可在集成的「配置」里改回路数量、轮询间隔和回读开关（会自动重载）。

## 变成真正的「灯光」实体

继电器在 HA 里是 `switch`，要走「打开客厅灯」这种语义，推荐用内置的
**Switch as Light** 辅助功能，不用写 YAML：

> 设置 → 设备与服务 → 辅助元素 → 创建辅助元素 → **Switch as Light**
> → 选择 `switch.deng_guang_ji_dian_qi_ch1`

之后就得到 `light.*` 实体，可加进房间、支持语音控制「打开灯」。

## 全开 / 全关

集成注册了一个服务 `modbus_relay.turn_all`，会逐路下发指令：

```yaml
service: modbus_relay.turn_all
data:
  state: false   # true = 全开，false = 全关
```

## 一些实测到的注意点

1. **透传设备通常只允许一个 TCP 连接。** 集成保持长连接，因此 HA 连着的时候，
   电脑上的 Modbus 调试工具会连不上（现象是连上立刻被断开）。调试时先停用集成。
2. **点按后 UI 立即变化，10 秒内由轮询校正为硬件真实状态。** 所以手动在模块上
   按按钮改变的输出，最多 10 秒后会在 HA 里同步过来。
3. **通信失败会自动重试一次**（断开重连后再发一次），适合透传设备踢掉空闲连接的情况。
   连续读失败会在日志里每 10 次报一次警告，不会刷屏。
4. 模块掉电后输出会复位，但**线圈寄存器掉电不保存**，所以重启 HA 后状态以轮询结果为准。
5. 如果模块实际波特率不是 38400（铁壳系列是 9600），透传设备侧波特率必须和模块一致，
   否则读不到任何响应。
